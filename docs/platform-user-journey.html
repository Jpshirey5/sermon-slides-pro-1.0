Sermon Slide Pro User Journey Documentation

Prepared from the current application implementation in sermon-slides-pro-1.0. This document is intended to be editable and usable for internal operations, onboarding, support, or investor documentation.

1. Product Summary

Sermon Slide Pro is a web platform for building sermon presentations. A user can arrive from the public website, create an account, choose a paid subscription, build a presentation from a sermon form, refine the result in a slide editor, and export the finished deck as either PowerPoint or ProPresenter. The product also supports a pay-per-export path for users who are not subscribed.

Primary user outcome How the platform supports it
Create sermon presentation slides quickly Structured sermon form with sermon points, verse references, translation selection, and automatic scripture lookup
Refine the visual presentation Slide editor with text, ordering, background, styling, preview, and autosave
Use slides in church presentation software Export to .pptx and .probundle
Stay active as a long-term customer Dashboard, saved presentations, subscription management, account profile settings, and team invites

2. Website Entry to First Conversion

2.1 Landing on the Website

The user enters the website on the public home page. The landing experience is organized around:

  • Hero section introducing the platform
  • Feature explanation
  • Testimonials/social proof
  • Pricing section
  • Call-to-action section

The public site is designed to move the user toward either a free creation flow or a paid Pro subscription.

2.2 Pricing Choices Presented to the User

Option Price User intent supported Primary call to action
Pay Per Export $9 per export User wants to create freely and pay only when exporting a specific presentation Go to the free creation flow
Pro Monthly $50/month User wants a persistent account, saved work, dashboard access, unlimited exports, and collaboration features Start signup and subscription checkout
Pro Yearly $500/year User wants the same Pro capability with annual billing Start signup and subscription checkout

2.3 Conversion Paths from the Homepage

There are two main user-entry paths after the homepage:

  1. Free/pay-per-export path: the user goes directly into presentation creation without needing an account to begin.
  2. Pro subscription path: the user chooses monthly or yearly Pro, creates an account, confirms email, and is redirected into Stripe checkout.

3. Account Creation and Login Journey

3.1 Standard Signup Flow

When a user signs up for Pro, the platform collects:

  • Full name
  • Email address
  • Password and password confirmation
  • Organization name
  • City
  • State

The platform validates required fields, password match, and password strength before allowing the user to continue.

3.2 Plan Selection During Signup

If the user reached signup from a pricing button, the selected plan can already be attached to the signup URL. If not, the user is shown a plan picker and chooses either:

  • Pro Monthly
  • Pro Yearly

3.3 Email Confirmation

After signup, the system creates the account and asks the user to confirm their email address. For new Pro users, the application stores a pending checkout state locally so that once the user confirms and logs in, the checkout process can resume automatically.

3.4 Login Flow

Returning users log in with email and password. If authentication succeeds, they are sent to the dashboard or to the originally requested protected page. If the session was ended by inactivity or a security event, the user is informed during login.

3.5 Invite-Based Signup Flow

The application also supports invited users. In that path:

  • The invite token is verified
  • The invited email is prefilled and locked
  • The user completes signup for the existing organization
  • The user is taken into the dashboard after account confirmation/login

4. Subscription Payment Process

4.1 When Subscription Checkout Starts

Subscription checkout can start in three places:

  • From the public pricing section
  • From signup after email confirmation
  • From the account page when an unsubscribed user is required to activate Pro

4.2 Checkout Preparation

Before opening Stripe, the system:

  • Confirms the user is authenticated
  • Finds the user’s account record
  • Finds or creates a Stripe customer
  • Saves the Stripe customer ID to the organization account
  • Checks whether the user already has an active subscription

4.3 Stripe Checkout Session

If the user is not already subscribed, the system creates a Stripe subscription checkout session using the selected monthly or yearly price. The success and cancel destinations are:

  • Success: dashboard with a successful checkout state
  • Cancel: account page

4.4 Successful Subscription Outcome

After successful payment:

  • The user is returned to the dashboard
  • The app refreshes subscription status
  • A welcome message confirms the subscription is active
  • The user now has full Pro access

4.5 Ongoing Subscription Management

From the account page, a subscribed user can open the Stripe customer portal to:

  • Manage subscription status
  • Resubscribe if cancellation is pending
  • Review renewal timing
Important product behavior: protected areas such as the dashboard and dashboard-based creation flow require an active subscription. Unsubscribed authenticated users are redirected to the account page to activate a plan.

5. Presentation Creation Process: Form to Generated Slides

5.1 Entry Into the Creation Flow

The user enters the creation flow by choosing Create from either the public site or the dashboard. The dashboard version is the Pro workflow. The public version also supports guest usage.

5.2 Sermon Form Inputs

The presentation builder starts as a structured form. The user can define:

  • Presentation title
  • Bible translation
  • Verse breakdown mode
  • Sermon points
  • Verse sections
  • Multiple scripture references within a section

5.3 Content Block Types

Block type User enters Result in generated slide set
Point A sermon point title A point slide is created
Verse One or more scripture references Scripture slides are created from the lookup results

5.4 Scripture Lookup

As the user types scripture references, the application automatically looks them up after a short delay. Lookup results are attached to the form state. If the lookup fails, the interface reports the error so the user can correct the reference.

5.5 Translation and Breakdown Behavior

The user can choose a Bible translation, and the system can regenerate scripture text against that translation. The user can also choose how scripture is split:

  • Verse-by-verse: each verse becomes its own slide
  • Full verses: the passage stays together in larger scripture slides

5.6 Reordering During Form Creation

The user can reorder sermon points and verse sections before generating slides. This ensures the sermon structure and presentation flow match the intended delivery order.

5.7 Save and Continue to Editor

When the user submits the form, the application:

  • Creates or updates the presentation record
  • Stores the source form data
  • Calculates the slide count
  • Opens the slide editor for visual refinement

For authenticated users, the presentation is saved in the backend. For guest users, it is stored locally in browser storage.

6. Slide Editor Process: Generated Slides to Final Presentation

6.1 Initial Slide Generation

When the editor opens, it loads saved editor slides if they already exist. If not, it generates a default slide deck from the sermon form data. The generated deck includes:

  • A title slide
  • Point slides for sermon points
  • Scripture slides for looked-up verses

6.2 Editing Capabilities

Inside the editor, the user can:

  • Select slides individually or in groups
  • Reorder slides
  • Add new slides
  • Delete slides
  • Edit text content
  • Adjust fonts and colors
  • Adjust line spacing
  • Apply or upload background images
  • Preview the deck before export

6.3 Autosave Behavior

The editor autosaves changes after the user modifies slides. This applies to slide-level design changes, allowing users to return later without losing progress.

6.4 Background Media Handling

If the user uses custom background images, the application resolves and stores those media assets. When slides are removed or changed, the system cleans up obsolete stored backgrounds where appropriate.

6.5 Editor as the Main Working Surface

At this stage the user has moved from structured sermon data entry into active presentation production. This is the primary daily-use surface for a repeat customer because it turns the generated draft into a polished, stage-ready deck.

7. Export Process and Export Payment Flow

7.1 Export Decision Logic

When the user clicks Export, the platform checks which access model applies:

User type What happens next
Active Pro subscriber Export options open immediately
Non-subscriber with prior unlock for this sermon Export options open immediately
Non-subscriber without unlock One-time payment prompt opens

7.2 One-Time Export Payment

For non-subscribers, the system offers a one-time export unlock priced at $9. This unlock is tied to the individual presentation and supports unlimited downloads for that presentation after payment.

7.3 Checkout Preparation for Pay-Per-Export

Before redirecting the user to Stripe for one-time payment, the app:

  • Saves current editor slides
  • Stores pending export context locally
  • Stores a snapshot of the presentation so it can be restored after the Stripe round trip if needed

7.4 Stripe Return After One-Time Payment

After successful payment, the user returns to a payment-success page. The app then:

  • Finds the pending sermon ID or snapshot
  • Restores the presentation if necessary
  • Returns the user to the editor with a successful payment state
  • Marks export as unlocked for that presentation
  • Immediately opens the export options modal

7.5 Export Options Presented to the User

Format Description Result
PowerPoint (.pptx) Microsoft PowerPoint-compatible presentation file Downloads a widescreen PowerPoint deck
ProPresenter (.probundle) Bundle export for ProPresenter with media support Downloads a ProPresenter bundle containing presentation data and background media

7.6 Export Validation

Before the file is produced, the platform validates the slide deck. If required slide content is missing or invalid, export is blocked until the issue is corrected.

7.7 Export Completion

After export succeeds, the file is downloaded to the user’s machine. The user can continue editing and export again as needed.

8. Dashboard and Ongoing Full-Time User Journey

8.1 Dashboard as the Main Hub

For a subscribed user, the dashboard is the default operational home. It provides:

  • Welcome state
  • Quick action to create a new presentation
  • A list of saved presentations
  • Direct access back into the editor
  • Ability to delete presentations

8.2 Saved Presentation Lifecycle

A full-time user typically repeats the following cycle:

  1. Log in to the dashboard
  2. Create a new presentation or reopen an existing one
  3. Edit sermon content and slide styling
  4. Export for service use
  5. Return later to duplicate, revise, or rebuild the next sermon deck

8.3 Account Settings and Profile Maintenance

From the account page, a full-time user can manage:

  • Full name
  • Default Bible translation
  • Subscription plan and status
  • Renewal or cancellation state

8.4 Team and Collaboration

For organization owners, the account page also supports team operations:

  • View team members
  • Invite additional users by email
  • Track pending invites
  • Resend invites

This is part of the long-term value of the subscription model because it turns the platform from a one-person tool into an organization-level workflow.

8.5 Long-Term Customer State

A mature, full-time platform user is someone who:

  • Maintains an active Pro subscription
  • Uses the dashboard as a regular weekly workspace
  • Stores multiple sermon presentations over time
  • Uses account settings and subscription management when needed
  • Potentially adds collaborators to the same organization account

9. End-to-End Journey Summary

  1. The user lands on the public website.
  2. The user reviews features, testimonials, and pricing.
  3. The user chooses either a free creation flow or a Pro subscription flow.
  4. If pursuing Pro, the user signs up, confirms email, and completes Stripe subscription checkout.
  5. The user enters the dashboard and starts a new presentation.
  6. The user fills out the sermon form with points, verses, translation, and breakdown preferences.
  7. The system performs scripture lookup and saves the presentation source data.
  8. The user is taken into the slide editor.
  9. The user edits slide order, text styling, backgrounds, and presentation design.
  10. The user clicks export.
  11. If subscribed, export proceeds immediately. If not subscribed, the user can unlock export for that presentation with a one-time $9 payment.
  12. The user downloads the presentation as PowerPoint or ProPresenter.
  13. As a full-time user, the person returns to the dashboard regularly to create, manage, and export future presentations.

10. Operational Notes

  • The application supports both guest/local-storage usage and authenticated account-based usage.
  • Protected subscription-only areas redirect unsubscribed users to activate billing.
  • Subscription management is handled through Stripe’s customer portal.
  • Pay-per-export users are still able to create and edit before paying.
  • The system includes fallback restoration logic after one-time export payment so a presentation can be recovered even if local state needs to be rebuilt.
